# Contributing to 30 Days of Java

Thank you for your interest in contributing to the 30 Days of Java Challenge! This document provides guidelines for contributing.

## How to Contribute

### Reporting Issues
- Use the GitHub issue tracker
- Describe the issue clearly
- Include steps to reproduce (if applicable)
- Mention the day/topic where the issue was found

### Suggesting Enhancements
- Open an issue with the "enhancement" label
- Describe your suggestion in detail
- Explain why it would be useful

### Contributing Code

1. **Fork the repository**
2. **Create a branch**
   ```bash
   git checkout -b feature/your-feature-name
   ```

3. **Make your changes**
   - Follow the existing code style
   - Add comments where necessary
   - Ensure code compiles without errors

4. **Test your changes**
   - Compile and run the code
   - Verify examples work correctly

5. **Commit your changes**
   ```bash
   git commit -m "Add: brief description of changes"
   ```

6. **Push to your fork**
   ```bash
   git push origin feature/your-feature-name
   ```

7. **Create a Pull Request**
   - Provide a clear description
   - Reference any related issues

## Content Guidelines

### Adding New Examples
- Include clear comments
- Follow Java naming conventions
- Provide output examples
- Keep examples simple and focused

### Writing Documentation
- Use clear, concise language
- Include code examples
- Add practical use cases
- Maintain consistent formatting

### Code Style
- Use 4 spaces for indentation
- Follow Java naming conventions:
  - Classes: PascalCase
  - Methods/Variables: camelCase
  - Constants: UPPER_SNAKE_CASE
- Add JavaDoc comments for public methods

## Questions?

Feel free to open an issue if you have questions about contributing.

Thank you for helping make this resource better! 🚀
